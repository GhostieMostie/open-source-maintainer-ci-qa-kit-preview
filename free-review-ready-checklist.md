# Free Review-Ready Checklist

Before opening a PR or posting a paid-work follow-up, check these five things.

## 1. Is There New Evidence?

Post only if you have something useful to add:

- reproduction steps
- local validation results
- CI status
- risk or rollback notes
- a real blocker summary

## 2. Can The Reviewer Verify It Quickly?

Give the reviewer a fast path:

1. What changed?
2. Why is this the smallest useful fix?
3. What command or screen proves it?

## 3. Are Payment Facts Public And Concrete?

Safe facts:

- bounty link
- visible amount
- platform or payment route
- public assignment or claim evidence

Unsafe claims:

- "I am assigned" without proof
- "payment is guaranteed"
- "I finished first, so this should be accepted"

## 4. Is CI Failure Code-Actionable?

Separate:

- code failures you can fix
- maintainer-owned secrets
- deployment authorization
- flaky infrastructure
- neutral skipped checks

Do not hide failures. Classify them.

## 5. Would This Comment Be Useful Without Money Attached?

If the answer is no, rewrite it.

A strong follow-up reduces reviewer work. A weak follow-up just asks for attention.
